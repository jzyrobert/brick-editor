# Agent-assisted MPD instruction authoring: three refinement rounds

> Generated evaluation outputs referenced below are retained locally, outside
> this PR. See the [artifact policy](README.md#local-artifacts).

The experiment gives agents checked authoring and rendering tools rather than
asking them to emit opaque occurrence IDs or treating a generated baseline as a
buildability certificate. It targets hobbyist builders. The reusable entry points
are the [workbench reference](../../AGENT-INSTRUCTIONS.md),
[agent prompt](../../../prompts/instruction-agent.md) and
[script](../../../scripts/instruction-workbench.ts).

Four fixed models received three cumulative proposal → actual render → independent
critic rounds. Two builder agents each revised a sample and an official-set OMR
model. The [critic](agent-workflow-critic.md) used a fixed five-point rubric:
3 means a useful editable draft with specific unresolved decisions; 4 requires
largely self-contained guidance; 5 requires actual builder evidence. No physical
assembly was performed. Different inputs and cumulative feedback make this a
workflow pilot, not an agent ranking or randomized comparison.

## What the tools do

`prepare` pins raw-source and native-model hashes, library locks, source
attribution and a deterministic baseline. It maps every expanded occurrence to a
stable alias and records exact poses, source groups, contacts, bounds and generated
drawing owners. `inspect` queries compact summaries or particular interfaces;
truncation is explicit and the complete dossier remains available.

`apply` resolves aliases into a native editable plan and validates exact-once
introductions, whole drawing owners, nested workbench ownership and destination
receivers. Child modules join their parent before the parent is placed. Scene
placements assert positioning without inventing a connection. It keeps authored
plans first on native opening and supplies pictorial views without stale generation
or CAD claims. Source geometry, source namespace and inventory are unchanged.

`review` captures the real shared compositor using stable operation keys and
bounded adjacent windows. Its manifest records source/plan/tool hashes, actual
masks, cameras, pixels and timing. Camera overrides change diagrams; they do not
simulate insertion or instruct a physical flip. Source-derived local-part bounds
are for framing only and do not grant verified connectors.

## Refinement sequence

Round 1 established separate objects, nested wheel workbenches and more purposeful
operations. It exposed tiny or concealed receiving interfaces, scene labels that
resembled attachment labels, excessive per-part markers on a whole-module join,
and a large dossier that encouraged broad inspections. Both official drafts still
needed critical procedure reconstruction. The initial target-count correction and
prepare overwrite guard happened before the round-1 capture freeze and are not
additional refinement rounds.

Round 2 added compact interface queries, key-based adjacent reviews, exact view
overrides, whole-module J/scene S markers and bare receiving masks for ordinary
additions. Builders exposed roof frames, wheel holders, Shark ball/socket mouths
and the jaw handle. Shark's honest independent/symmetric batches reduced its plan
from 228 to 193 operations without dropping occurrences. Count reduction itself
was not credited as usability. Both official cases reached useful-draft scores.

Round 3 tightened bare-rim details, Truck wrist socket/printed-face views and Shark
tail hinge fingers. Captions distinguish loose support, holding and possible
physical reorientation from merely changing a camera. The tool now reports
operation/field-specific camera schema failures and rejects incoming-module views
on ordinary additions. The prompt/reference explain source-alias prerequisite
pairs and the complete camera schema.

Actual publication and phone checks exposed and repaired shared issues before
final evidence: authored pictorial plans must retain that presentation flag through
publication, and R/J/S/P interface captions must survive incoming-lot naming.
The live editor/viewer now also removes ordinary additions from its receiving
view, using a shared mask helper; the earlier compositor correction alone did
not cover those controls. A production browser regression checks visible IDs
before and after that action. File-local shadow parts now use their own source titles. These are presentation
and source-identity fixes, not automatic assembly planning or verified fit.

## Limits and next useful work

Exact source and replay audits pass for all four final plans, with 58/281/86/230
unique introductions. No generated insertion claims or physical trials are
inherited. Unknown detachable stability, figure supply state, flexible identity,
small printed details and unsupported joints remain explicit review tasks.

The compact summary is a bounded query, not an equivalent compression of the full
dossier. Logged render timings are single runs on software WebGL; no token cost,
agents' reasoning time, physical-device performance or broad superiority is
claimed. Automatic nested planning remains separate work: this feature enables
agents to author nested programmes deterministically, while the heuristic
baseline remains v9.
