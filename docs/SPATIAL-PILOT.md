## Transport and quota boundary

The first seven creative cases used archived `codex-text-broker/2`; the remaining 65 used `codex-guarded-broker/4`, adding evaluator-only frozen image hashes, cancellation handling and typed model-budget failures. Calibration used v2; review used v4. Each phase archives its actual adapter source, binary hash, bridge hash, exact effective native request and response stream. Native instructions add transport context beyond the filled E prompt. Controls and treatments share the transport in each phase; historical native runs are not replacement controls. The phase change and interruptions are limitations of this pilot, not a transport-performance comparison.

The native client runs in a fresh Bubblewrap filesystem/network namespace. Only approved text, credential-free private client state, runtime libraries, the client binary and a Unix transport socket are mounted. The host broker allows only the fixed Codex subscription Responses endpoint, forces Sol 6.1/high and an empty native tool list, denies non-text generation inputs and undeclared actions, and logs denied routes. Authentication stays on the host. Each case starts a fresh session; within-case catalogue/check dialogue resumes only its own isolated thread. Compilation remains a separate sandbox.

Quota is read through `account/rateLimits/read` before and after every provider request and every completed case. The reserve is at least **5 percentage points**, or twice the largest observed case drop. Missing quota data blocks further generation. This is a conservative gate, not a guarantee against concurrent account usage. No quota reset or paid-credit operation is called. The calibration stage's recorded account readings moved from 51% to 50% remaining; these readings include activity outside the experiment.

One initial launch failed before any model request because the Unix socket pathname was too long; it is retained separately. V2 used a short temporary socket pathname. Infrastructure retries are zero within a study; the corrected launch has its own version and directory. An initial renderer smoke check failed on missing render quality, then a separate corrected smoke check produced four images. Neither is a model-quality result.

### Exact-count audit correction

The frozen briefs explicitly require 16 parts, but the runner's `targetParts` does **not** enforce exact counts at final acceptance. It checks compiler errors and inventory maxima. The final independent audit found one originally submitted Luna control (`canal-landing--control--1`) with **14 parts**. Earlier progress reports calling every accepted build 16 parts were therefore incorrect.

The [post-evaluation audit](../fixtures/spatial-benchmark/studies/model-screening-pilot/results/exact-count-audit.json) preserves original statuses and scores and reports strict task compliance separately. Luna has eight compliant submissions, seven originally recorded model failures and one additional task-count violation. The 14-part build received an automated score before this audit; that score is retained but excluded from the compliant-only mean. It does not change the paired Luna effect because the canal already had no surviving combined case. All submitted Sol and Astra builds have 16 parts. The count rule is taken from the original task brief, not selected after observing scores. The audit is explicitly post-evaluation, not a preregistered metric. Future exact-count studies need an explicit versioned size policy and evaluator eligibility check before review; legacy target semantics are preserved here.
