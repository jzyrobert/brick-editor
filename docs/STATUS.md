# Implementation status

This report distinguishes working implementation from the full specification. The delivered scope is a usable core editor with selected later editing/reliability features. **It is not a supported full P0 release, with basic M4 exploration now implemented independently. Selected M4 publishing and M5 kinematic mechanisms are also implemented. The full roadmap remains incomplete.**

## Remaining release gates

M0/M1 demonstrate the architecture and 200-part workflow, but the complete risk-reduction checklist still has gaps. Wider compatibility is not inferred from the starter palette.

- **M0 contracts/conformance:** whole-library BFC coverage beyond independently rendered ancestor/internal-dependency fixtures and broader conditional-line image comparisons, complete custom material/finish scope, source-preserving embedded image assets beyond opaque records, full geometry compiler budgets, source closure/thumbnail generalization and reference-hardware measurements. Current tests use a Linux ARM64 VM and software WebGL, as requested, not physical devices.
- **M2 editing:** connected-assembly selection; general pivot workflows; collapsible folder trees; noncontiguous structural regrouping; connector workplanes; globally optimized or connector-aware packing beyond the implemented deterministic allowed-part tiling; favourites/recent catalogue features.
- **M3 reliability:** automatic portable-library installation and audited colour-configuration redistribution; broader stateful-metadata export coverage; comprehensive asset/texture/native migrations; broader storage recovery coverage; user lighting/clipping controls and broader graphics-driver recovery coverage; incremental renderer change sets and broader instancing performance measurements; larger security corpus and physical-device budgets.
- **M3 inventory:** verified composites/decomposition and ambiguity candidate UI; historical invalid-combination data beyond curated coverage; inventory override undo under future structural regrouping; all optional Wanted List price/quantity fields; fixture packs for printed/left/right variants; human-authorized BrickLink destination upload test (**not performed**). No purchases, uploads, credentials or accounts were used.
- **M4:** validated connector packs/snapping; broader texture rendering and offline packs; instruction callouts/arrows/exploded offsets, assembly drafts; remaining exploration acceptance, advanced rig authoring and larger collision fixtures.
- **M5/M6:** dynamic physics and suspension, advanced assembly planning, path tracing, inventory-constrained generation and separately scoped collaboration.

The user explicitly reprioritized working Play ahead of the unfinished P0 gates. Basic exploration now includes Rapier capsule walking, gravity/jump/steps/slopes, safe fly transitions, first-person and sphere-swept third-person cameras, an original rigid-joint avatar, fixed 60 Hz tick control and editor-state isolation. Hinge/vehicle previews and explicit undoable pose application now have browser evidence; broader PL compatibility remains unverified; no complete P0 release is claimed.

## Deliberate limits

- Domain: 25 MiB source/archive input, 100 MiB decompressed data, 10,000 definitions, depth 64, 100,000 expanded leaves, 10,000 additions per command. Some ancillary schema dictionaries have their own smaller caps.
- Reference renderer: 5,000 leaf occurrences, 128 prototype variants, 50 MiB multiplied custom compilation source. Crossing a render budget retains the document and non-graphics export. Performance at those limits is not promised.
- PNG: 16 megapixels and device texture limits. Tiling is not implemented.
- History: 100 entries / about 8 MiB JSON patch budget. Deduplication: 500 session entries.
- Mapping: six part identities; five audited colours each. Other mapped combinations require an explicit acknowledgement. No current availability or universal physical buildability claim.
- Offline installation is explicit. The versioned app, Play/PDF chunks and pinned starter library are cached together; previous snapshots remain installed. First visit still requires a connection.

See [ARCHITECTURE.md](ARCHITECTURE.md) for the reasoning behind deviations and [reports](reports) for actual verification/performance evidence.

## Editing expansion

Transform handles preview world-space movement/rotation without document changes and commit one undoable transaction. They preserve full affine placements and have numeric alternatives; up to 1,000 selected occurrences are supported. Box/lasso visible-surface selection uses a depth-tested ID image at CSS-pixel resolution, with every visible layer acting as an occluder before editing scope is applied. Through-selection tests clipped triangles, including surface crossings without projected centres inside the region. Line-only helpers do not count as surfaces; subpixel surfaces may have no CSS-pixel sample. Work is bounded by four million pixels, 2,048 lasso points, five million triangle tests and twenty million polygon-intersection work units.

Nested folders organize layers while global layer order, visibility and locks remain explicit per-layer settings. Duplicating a layer preserves source-aware placements, applicable overrides/groups/instruction plans and folder membership under new IDs; opaque metadata and motion rigs that cannot yet be remapped are refused explicitly. Ghosting is an editing-only view and never alters authored state or exported image opacity.

Scoped LDraw export now retains the selected paths through parent definitions, material/BFC records and embedded dependencies. Deleting a reference removes its orphaned INVERTNEXT directive; reflected raw polygon export reverses winding. These source/semantic regressions do not establish universal rendered ancestor-BFC equivalence.

## Workplane, model and reliability checkpoint

World, picked-triangle and numerical workplanes control rigid placement orientation, elevation, grid and free placement. Fill previews respect the plane basis and use conservative transformed obstacle bounds. Connector workplanes remain unavailable without verified connector data.

Make-submodel preserves full affine placement and occurrence-scoped metadata for contiguous sibling selections. Make-unique isolates an instance; explicit shared-edit previews support recolour and local translation with complete affected-scope checks. Unsupported source state, noncontiguous regrouping and rig-rest translation are refused. Local-pivot shared rotations were added in the subsequent checkpoint below; general structural editing remains unfinished. Keyboard and UI clipboard now share one fragment; shortcuts are configurable and persisted locally.

Standard, portable, layer-archive and native export profiles are available through UI, API and CLI. Layer MPDs preserve world coordinates. Optional official geometry archives contain exact hash-verified licensed files, dependency closure and notices while preserving official purchasing identity. Extract the archive and configure its library search path: direct ZIP import and audited redistribution of the pinned colour configuration remain unavailable. Native export includes the whole project. Export work is bounded, cancellable and revision checked.

Browsers without Web Locks use an exclusive IndexedDB transaction across asynchronous save checksums. Missing coordination disables automatic writes and offers backup; expired locks cannot publish late writes. Other-tab notifications preserve the draft, with fork or backup-before-reload choices. A stale failed save from a previously open project cannot mark the new project conflicted.

Ancestor and internal-dependency BFC contexts now have an original seven-case fixture compared to an independently loaded, hand-expanded MPD from front and back. This closes the demonstrated context propagation bugs, not universal library conformance. Mobile re-review remains **8.7/10**, with screenshots in UX-AUDIT.

## Exploration, instructions and graphics recovery

Play can include one authored kinematic rig. Its rigid groups use transformed triangle colliders and fixed-tick poses, allowing an opened door to become traversable. Swept movement is conservatively refused before a moving surface touches the walking explorer. This is not vehicle/world dynamics, riding or pushing. Moving geometry is bounded to 128 groups and 200,000 triangles; commands exceeding 1,024 swept segments must use smaller targets. Runtime joint/vehicle controls preserve the authored document.

Instruction plans now support create/rename/delete, step add/remove/reorder/split/merge, occurrence reassignment, notes and saved cameras through undoable commands. Camera presets remain accessible in Instructions. Optional aligned metadata preserves older plans, survives clipboard filtering and native saves, and is honored by JSON/HTML/PDF publication. Publication still requires exact coverage and restores the original camera. Callouts, arrows, exploded offsets, assembly planning remain unfinished.

Graphics loss aborts readiness/capture waits and shader polling with a structured error. Three rebuilds GPU state from retained geometry/materials on restoration; repeated real context-loss tests preserve edited documents and native backups with identical restored captures. The capture path owns bounded shader polling because the pinned renderer's asynchronous compiler cannot cancel its timer. This evidence uses software Chromium and does not certify every driver.

## Play settings and view isolation

The pause menu exposes bounded eye height, field of view, near plane, follow distance and pitch limits. Camera changes preserve the fixed walking collider; captures account for their own aspect ratio. Validated session spawn points support typed positions and saving the current supported position, and are revalidated before use. Nine Play keyboard actions are remappable with duplicate checks and device-local persistence; Escape always pauses. These preferences do not alter the authored model. Instruction previews defer renderer changes during API Play, then restore the selected instruction camera and visibility on exit.

## Explicit Play world and instruction appearance

Play entry now accepts a session world profile excluding chosen layers from both visible geometry and collision. Editor hidden/locked state does not exclude geometry by default; the entry UI separately controls temporary ground. A selected moving rig requires all of its member layers. Captures intersect their requested scope with the active Play profile, and exit restores editor visibility. Reports record the frozen inclusion profile.

Instructions can dim previously introduced parts in preview and PNG/HTML/PDF publication while retaining the original appearance of current additions. The appearance treatment does not alter project materials or hide prior geometry. Shared definition editing now includes rotation around a declared local pivot, preserving existing affine transforms and requiring the same all-instance impact preview, lock/scope checks and undo as other shared edits. Rotations affecting authored rig rest geometry are refused.

## Allowed-part fills and rig creation

Allowed-part fills use deterministic largest-first packing of same-height audited parts with quarter turns, optional cell masks, bounded search, cancellable worker previews and one-command commits. Hidden geometry remains an obstacle; unknown/custom-overridden parts block placement conservatively. This is neither globally optimal packing nor verified connectivity.

The Inspector can create hinge and planar vehicle rigs using explicit member assignments, axes and world pivots, with transient preview, revision guards, native persistence and undo. Rig replacement/removal now checks old memberships as well as new memberships for locks/scope. The following checkpoint adds supported edit/removal workflows. Compound-rig and arbitrary-frame UI, suspension and vehicle/world dynamics remain open.

## General joint editing and structured queries

Representable single-joint and pure planar vehicle rigs now support guarded load/edit/remove workflows. Fixed, revolute, prismatic and spherical definitions preserve explicit frames, custom axes, IDs, optional limits and motor metadata during supported edits. Spherical preview remains rest-only, motors are not actuated, and unsupported compound topologies are refused rather than flattened. Arbitrary frame-authoring UI and dynamic assemblies remain open.

Browser and CLI queries now include submodel/selection scopes, counts, source-derived conservative bounds, unknown-geometry IDs, nested unresolved dependencies, physical-transform diagnostics and bounded overlap candidates without WebGL. Connectivity is explicitly unverified until a verified connector pack exists. Source boxes are checked against the pinned library closure in CI; overlap candidates do not establish physical collisions or buildability.

A contract audit also reproduced an open M0 gap: valid deeply nested UUID occurrence paths can exceed the generic 1,024-character schema limit. A 32-level fixture produces a 1,249-character path that queries cannot accept by ID. This requires a coordinated occurrence-ID and aggregate-request budget fix across query, scope and command schemas; it is tracked in TODO.

## Nearby Play interaction

The selected Play rig now exposes a contextual button and remappable E action within 96 LDU of its authored joint anchor or vehicle chassis, measured from the explorer's body center. Revolute and prismatic joints toggle between the allowed position nearest zero and the farthest limit (defaults: 90 degrees or 40 LDU). Motion still uses the swept actor-clearance checks and reports a blocked attempt visibly. This is proximity access, not a line-of-sight picking system or automatic door detection.

Vehicle access switches movement keys and the touch joystick to throttle/steering, with an explicit Release vehicle action. The explorer remains on foot; pause, focus loss and released inputs stop driving. Look controls remain available. The authored build is unchanged. Only the selected rig is active; simultaneous nearby rigs, animated door travel, seated entry/exit, riding and vehicle/world collision response remain open.

## Multiple active Play rigs

Play can now activate all authored mechanisms or an explicit subset in one session. The nearest authored joint/chassis supplies the contextual action, and remote controls can select a specific active rig. Door poses persist while a different vehicle moves; all moving colliders and actor navigation share the fixed-tick world. Explicit per-rig API targeting avoids ambiguity. Combined limits are 32 rigs, 128 groups and 200,000 moving triangles; repeated IDs, overlapping members and excluded member layers are refused before simulation.

The legacy single-rig request/report remains supported. Vehicles are still kinematic and remotely controlled from the explorer's position, without seated entry, riding or vehicle/world response. Multi-rig support does not infer joints or controllers from arbitrary imported geometry.
