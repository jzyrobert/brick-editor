# Implementation status

This report distinguishes working implementation from the full specification. The delivered scope is a usable core editor with selected later editing/reliability features. **It is not a supported full P0 release, with basic M4 exploration now implemented independently. Selected M4 publishing and M5 kinematic mechanisms are also implemented. The full roadmap remains incomplete.**

## Remaining release gates

M0/M1 demonstrate the architecture and 200-part workflow, but the complete risk-reduction checklist still has gaps. Wider compatibility is not inferred from the starter palette.

- **M0 contracts/conformance:** ancestor BFC propagation during independent leaf rendering and broader conditional-line image comparisons, complete custom material/finish scope, source-preserving embedded image assets beyond opaque records, full geometry compiler budgets, source closure/thumbnail generalization and reference-hardware measurements. Current tests use a Linux ARM64 VM and software WebGL, as requested, not physical devices.
- **M2 editing:** connected-assembly selection; configurable pivots and shortcut remapping; collapsible folder trees; make-submodel/shared-definition editing; configurable face/connector workplanes; general allowed-part deterministic tiling; favourites/recent catalogue features.
- **M3 reliability:** fully portable/per-layer LDraw UI and archives; scope-aware stateful-metadata export review; comprehensive asset/texture/native migrations; complete multi-tab read-only/fork UX on browsers without Web Locks; user lighting/clipping controls and stronger graphics recovery tests; incremental renderer change sets and broader instancing performance measurements; larger security corpus and physical-device budgets.
- **M3 inventory:** verified composites/decomposition and ambiguity candidate UI; historical invalid-combination data beyond curated coverage; inventory override undo under future structural regrouping; all optional Wanted List price/quantity fields; fixture packs for printed/left/right variants; human-authorized BrickLink destination upload test (**not performed**). No purchases, uploads, credentials or accounts were used.
- **M4:** validated connector packs/snapping; broader texture rendering and offline packs; richer instruction editing, annotations and assembly drafts; remaining exploration acceptance, advanced rig authoring and larger collision fixtures.
- **M5/M6:** dynamic physics and suspension, advanced assembly planning, path tracing, inventory-constrained generation and separately scoped collaboration.

The user explicitly reprioritized working Play ahead of the unfinished P0 gates. Basic exploration now includes Rapier capsule walking, gravity/jump/steps/slopes, safe fly transitions, first-person and sphere-swept third-person cameras, an original rigid-joint avatar, fixed 60 Hz tick control and editor-state isolation. Hinge/vehicle previews and explicit undoable pose application now have browser evidence; broader PL compatibility remains unverified; no complete P0 release is claimed.

## Deliberate limits

- Domain: 25 MiB source/archive input, 100 MiB decompressed data, 10,000 definitions, depth 64, 100,000 expanded leaves, 10,000 additions per command. Some ancillary schema dictionaries have their own smaller caps.
- Reference renderer: 5,000 leaf occurrences, 128 prototype variants, 50 MiB multiplied custom compilation source. Crossing a render budget retains the document and non-graphics export. Performance at those limits is not promised.
- PNG: 16 megapixels and device texture limits. Tiling is not implemented.
- History: 100 entries / about 8 MiB JSON patch budget. Deduplication: 500 session entries.
- Mapping: six part identities; five audited colours each. Other mapped combinations require an explicit acknowledgement. No current availability or universal physical buildability claim.
- Offline installation is explicit. The versioned app, Play/PDF chunks and pinned starter library are cached together; previous snapshots remain installed. First visit still requires a connection.

## Editing expansion

Transform handles preview world-space movement/rotation without document changes and commit one undoable transaction. They preserve full affine placements and have numeric alternatives; up to 1,000 selected occurrences are supported. Box/lasso visible-surface selection uses a depth-tested ID image at CSS-pixel resolution, with every visible layer acting as an occluder before editing scope is applied. Through-selection tests clipped triangles, including surface crossings without projected centres inside the region. Line-only helpers do not count as surfaces; subpixel surfaces may have no CSS-pixel sample. Work is bounded by four million pixels, 2,048 lasso points, five million triangle tests and twenty million polygon-intersection work units.

Nested folders organize layers while global layer order, visibility and locks remain explicit per-layer settings. Duplicating a layer preserves source-aware placements, applicable overrides/groups/instruction plans and folder membership under new IDs; opaque metadata and motion rigs that cannot yet be remapped are refused explicitly. Ghosting is an editing-only view and never alters authored state or exported image opacity.

Scoped LDraw export now retains the selected paths through parent definitions, material/BFC records and embedded dependencies. Deleting a reference removes its orphaned INVERTNEXT directive; reflected raw polygon export reverses winding. These source/semantic regressions do not establish universal rendered ancestor-BFC equivalence.
