## Remaining release gates

M0/M1 demonstrate the architecture and 200-part workflow, but the complete risk-reduction checklist still has gaps. Wider compatibility is not inferred from the starter palette.

- **M0 contracts/conformance:** broader BFC/conditional-line image comparisons, complete custom material/finish scope, source-preserving embedded image assets beyond opaque records, explicit Play/rig schemas, full geometry compiler budgets, source closure/thumbnail generalization and reference-hardware measurements. Current tests use a Linux ARM64 VM and software WebGL, as requested, not physical devices.
- **M2 editing:** drag previews/transform handles; copy/cut/paste fragments; box/lasso/occlusion-correct and connected selection; layer folders/duplication/ghosting; UI layer deletion/reordering; make-submodel/shared-definition editing; configurable face/connector workplanes; linear/circular arrays and general allowed-part deterministic tiling; favourites/recent catalogue features.
- **M3 reliability:** fully portable/per-layer LDraw UI and archives; scope-aware stateful-metadata export review; comprehensive asset/texture/native migrations; complete multi-tab read-only/fork UX on browsers without Web Locks; 3-second autosave maximum under sustained input; primitive/custom geometry duplication; render quality presets, lights/shadows/clipping controls and stronger graphics recovery tests; incremental renderer change sets and measured instancing; larger security corpus and physical-device budgets.
- **M3 inventory:** verified composites/decomposition and ambiguity candidate UI; historical invalid-combination data beyond curated coverage; inventory override undo under future structural regrouping; all optional Wanted List price/quantity fields; fixture packs for printed/left/right variants; human-authorized BrickLink destination upload test (**not performed**). No purchases, uploads, credentials or accounts were used.
- **M4:** validated connector packs/snapping; broader texture rendering and offline packs; richer instruction editing/assembly drafts/PDF; bounded share links; walk/free-flight/first-person/third-person exploration and all PL acceptance tests.
- **M5/M6:** kinematic mechanisms, physics, advanced assembly planning, path tracing, inventory-constrained generation and separately scoped collaboration.

The P0 omissions above keep the gate for exploration closed. Play shows an explicit unavailable state rather than a nonfunctional imitation of walking controls.

## Deliberate limits

- Domain: 25 MiB source/archive input, 100 MiB decompressed data, 10,000 definitions, depth 64, 100,000 expanded leaves, 10,000 additions per command. Some ancillary schema dictionaries have their own smaller caps.
- Reference renderer: 5,000 leaf occurrences, 128 prototype variants, 50 MiB multiplied custom compilation source. Crossing a render budget retains the document and non-graphics export. Performance at those limits is not promised.
- PNG: 16 megapixels and device texture limits. Tiling is not implemented.
- History: 100 entries / about 8 MiB JSON patch budget. Deduplication: 500 session entries.
- Mapping: six part identities; five audited colours each. Other mapped combinations require an explicit acknowledgement. No current availability or universal physical buildability claim.
- No service worker yet: in-session cached starter geometry and offline inventory work; first-visit/offline app-shell installation is not promised.
