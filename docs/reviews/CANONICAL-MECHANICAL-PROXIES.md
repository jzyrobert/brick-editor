# Canonical mechanical proxies

Reviewed moving beam, gear and rack surface proxies can consume occurrence-bound `memberLocals` captured from the loaded part prototype. Their vertices remain in part-local coordinates while a rigid child pose composes the occurrence through its group frame. This avoids transforming source vertices into world Float32, undoing that transform, then asking the native hull builder to reconstruct thin solids.

The existing reviewed surface skins and beam bore envelopes remain simulation approximations. This change neither supplies the pending positive-volume rack housing nor removes the recognized guided-rack Play refusal. Legacy callers without canonical member geometry retain the existing world-source path. The renderer producer owns source revision, occurrence, namespace, render-context and authored-frame validation.

The rigid pose uses the same `orthonormalized` realization of accepted rounded LDraw rotations as mechanical feature matching. This preserves the existing proper-rotation acceptance envelope; scaled, mirrored and project-namespace parts do not acquire reviewed official feature support. Native hull vertices are never rotated through the authored pose. Native child positions and rotations are composed together; grouped shapes flatten one-child wrappers and retain the true aggregate child count. Canonical hulls must pass raw native admission before any world collider is created.

Verification: `tests/unit/play-canonical-mechanical-solids.test.ts` applies a 37-degree rotation about [1,1,1] and a translated rest frame to the actual pinned Technic spur fixture. Every prepared child admits natively, no nested compounds remain, the aggregate count stays below 4096, and both native and kinematic modes reach input 90 degrees / output -30 degrees without changing the project JSON. The backend test uses the shared helper that captures the original occurrence context in identity part coordinates; renderer capture and override coverage are also verified separately by the producer. It is an oblique geometry/admission/contact test, not a phone performance or rack acceptance claim.
