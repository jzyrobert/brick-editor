# Reversible gripper attachments

> **Engineering scope:** these mathematical/native fixtures remain available for
> engine verification and lossless project storage. Ordinary Play requires real,
> reviewed part connections and currently refuses these unbound mechanisms.
> See [physical Play admission](PLAY-PHYSICS.md#physical-parts-in-ordinary-play).

An authored gripper can attach a nearby loose rigid group during Dynamic Play,
carry it through the existing native joint system, and release it back to ordinary
physics. A grasp creates one temporary fixed joint at the bodies' **current**
relative pose. It does not reposition either body or change either velocity.
Subsequent solver impulses reconcile motion and reflect the payload's mass,
inertia, gravity and obstacle reactions through the carrier's existing joints.

## Authoring and actions

Add explicit capture points to a complete motion-rig definition:

```json
{
  "grippers": [
    {
      "id": "claw",
      "groupId": "head",
      "anchor": [0, 20, 0],
      "captureRadiusLdu": 12,
      "maxPayloadMassKg": 100
    }
  ]
}
```

The anchor is group-local LDU. The radius measures distance from that live anchor
to the target **group origin**, not to every visible brick or its closest surface.
Authors should place payload origins deliberately. Mass is the existing Play
simulation mass at the 0.02 m/LDU gameplay scale, not a purchasing specification
or certification of a real claw's strength.

There are at most eight grippers per rig, one per group. Capture radius is positive
and at most 32 LDU; each local anchor component is within ±2048 LDU. Payload limits
range from 0.01 to 1000 kg. A gripper must mount to an actual native group; the
visual wheels of a ray-cast vehicle cannot serve as gripper bodies.

The automation actions return the current Play snapshot:

```ts
await window.brickEditor.play.grab({
  rigId: "crane",
  gripperId: "claw",
  target: { rigId: "cargo", groupId: "crate" },
});
await window.brickEditor.play.release({ rigId: "crane", gripperId: "claw" });
```

`mechanisms[rigId].grippers[gripperId]` reports the live anchor, available nearby
candidates, and any held target with its native mass. A target can belong to the
same rig or another active Dynamic rig. It must be explicitly unanchored and
otherwise loose: authored joints, closure edges, force links and vehicle rigs
make it ineligible. A group with its own gripper is also ineligible. Each payload
has one owner, and a gripper holds one payload. These restrictions prevent
attachment cycles and the removal or bypass of authored constraints.

All native contacts remain enabled, including the held pair. The grasp refuses a
holder/payload overlap deeper than 0.5 LDU; it never suppresses that collision to
make the attachment work. Admission checks at most 4096 collider pairs per grasp,
shares the existing 64-native-group limit, and allows at most sixteen live
attachments. Refusal allocates no joint and preserves body state.

## Play controls and overview

Dynamic remote controls show **Grab crate** when the authored capture zone has an
available candidate, and **Release crate** while holding it. Multiple nearby
candidates use a plain selector. Empty capture zones add no controls; Kinematic
Play shows no grab/release actions. Buttons retain 44 px touch targets and the
existing control sheet, scroll behavior and workshop colors.

While controlling a gripper mechanism, the automatic overview includes the held
group's cached source bounds and live frame even if it belongs to another rig.
Other loose groups stay out of that view. Release removes the extra bounds;
Fit and closing controls retain their existing behavior.

Paused or captured sessions reject grab/release mutations. Source revision changes
end the session. Exit and disposal remove temporary joints before freeing bodies;
re-entry starts with empty grippers. Release retains the current payload pose and
velocity and restores its previous native solver-iteration setting.

## Source, export and verified scope

The authored project, inventory, placements, original LDraw export and native
backup remain unchanged by a session. Native persistence retains the **gripper
definitions**, without held targets or temporary joints. Posed application and
undo retain those definitions; the basic rig editor and clipboard operations
refuse paths that would discard or incorrectly remap them.

Posed LDraw export includes every held occurrence at its current transform. It is
a static copy, with a warning that temporary Play attachment joints are absent.

The original CC0 fixture `fixtures/ldraw/gripper-lift.mpd`, generated by
`src/mechanisms/gripper-fixture.ts`, has five occurrences: a post, table, carriage,
head and separate loose crate. The carriage occupies a separate physical lane,
so lifting and carrying keep ordinary contacts active without rest interference.
The companion native project definition supplies two motors and the explicit
capture point; an ordinary LDraw import does not infer these mechanics.

This is a bounded ideal grasp for authored cranes and grippers. It does not
establish automatic claw articulation, frictional finger grasping, break force,
attachment through connector recognition, arbitrary player grabbing, articulated
payload recruitment, or walking on moving train cars. Browser phone layouts are
software-WebGL checks, not measurements of physical-phone frame rate.

The focused verification passes 35 unit tests and six production-rendered browser
cases at 1440×1000, 1080×1800, 360×600, 411×685, 390×844 and 686×411. Each browser
case lifts and carries a separate payload, releases it to free fall, compares
source and inventory before/after, restores every posed occurrence transform,
and checks pause/revision/re-entry behavior. Independent projection checks keep
all 32 selected-and-held group corners clear of the control sheet at each size.
Native tests additionally cover unchanged attachment poses/velocities, a heavy
payload stalling the same motor, a held payload blocked by an ordinary collider,
rotated frames, ownership/cycle/overlap refusal, the sixteen-attachment bound,
native persistence, posed application/undo and capture-time mutation refusal.
