# Judge a refined deterministic instruction draft

Use with WORKSPACE, baseline/refined natives, both capture packets and their
audits. Read [HYBRID-INSTRUCTIONS.md](../docs/HYBRID-INSTRUCTIONS.md).

Judge the actual pictures before reading the builder's rationale. Compare the
refinement against its pinned **latest** deterministic baseline, by stable action
keys and source occurrences. Inspect consecutive prior/current/next states and
critical unchanged wheel, figure, joint and receiving procedures. State exactly
which operations were viewed, which were reused with proven equivalence, and
which publication or phone checks are pending. Selected windows are not a full
visual study.

Independently check source references, namespaces, colours, raw poses, exact-once
inventory, whole drawing ownership, module replay and actual destination receiver
availability. Introduced parts on unjoined sibling benches are unavailable.
Retained support/host/access edges are hard constraints; empty graphs provide no
positive evidence of physical assembly. Changed contexts or views must not
inherit stale CAD routes or automatic generation claims.

Rate sequence, interface guidance, part finding, state/context, handling and
publication on the same 1–5 hobbyist rubric for both plans. Overall anchors: 1
requires reconstruction; 2 still requires substantial reconstruction; 3 is a
usable draft with specific gaps; 4 is consistently clear in the inspected scope;
5 has reference-level desk-review clarity. None certifies a physical build.
Do not reward more warnings, fewer steps, more modules or passing audits alone.

Name concrete improvements and regressions: hidden actual socket/clip mouths,
dependent additions in one picture, late interior work, undefined loose support,
missing build/place transitions, concealed prints or unreadable action notes.
Camera changes are views, not physical turns. An omitted-surroundings detail must
retain real context and explicit unknown fit/access. Check actual exported image
rectangles and complete captions; a valid JSON plan can still print badly.

Give each defect an action key, affected source aliases and an observable repair
criterion. Re-review changed pictures after a repair. Accept bounded useful
improvements even when the overall score stays unchanged, and preserve remaining
decisions and refusals. Deliver a paired score table, inspected-scope audit and
short verdict separating source/replay correctness, visual usability and unknown
physical outcomes.
